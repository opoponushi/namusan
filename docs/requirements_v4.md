## 0. 前提・位置づけ

- 本アプリは「制作者モード（自分用プレビュー・素材作りツール）」と「学習者モード（視聴者が操作して練習するアプリ）」の両方を将来的にカバーする。
- ただし一度に両方作り込むのではなく、**共通のコアエンジンを先に固め**、その上にモードごとのUIを後乗せする構成にする。
- 本アプリ自体は動画ファイル（MP4等）を直接書き出す機能は持たない。画面録画、または静止画連番書き出し＋外部ツール（ffmpeg等）で動画化する前提とする（9章参照）。

---

## 1. 全体アーキテクチャ方針

```
┌─────────────────────────────┐
│         コアエンジン           │  ← スケール／色／インターバル計算ロジック
│  （UIに依存しない純粋なロジック層） │
└─────────────────────────────┘
        │                  │
┌───────────────┐   ┌───────────────┐
│  制作者モードUI  │   │  学習者モードUI  │
│ （プレビュー・調整）│   │（練習・クイズ・進捗）│
└───────────────┘   └───────────────┘
```

- コアエンジンとUIを分離することで、後から学習者モードを追加してもロジックの二重実装を避けられる。
- 状態管理は「今のスケール」「中心音」「表示中のフレーズ」「再生位置」などをアプリ全体で一元管理する。

## 2. データモデル（要件レベル）

### 2.1 スケール定義（度数・記号） 🆕更新

音の地点（スケール上の音）は、①②③④…の数字表記だけでなく、**専用の記号**でも表現する（視覚的な学習効果を狙う）。

**度数記号一覧（クロマチック12種・確定）**

| 度数 | 記号 | 備考 |
|---|---|---|
| ① | ☆（星） | 基準音（トニック） |
| ♭2 | ■（黒塗りの横長長方形） | メジャースケール外 |
| ② | ▭（中空きの横長長方形） | メジャースケール上 |
| ♭3 | ▲（黒塗り三角） | メジャースケール外 |
| ③ | △（白抜き三角） | メジャースケール上 |
| ④ | □（四角） | メジャースケール上 |
| ♭5 | ●（黒丸） | メジャースケール外 |
| ⑤ | ○（白丸） | メジャースケール上 |
| ♭6 | ◐系（三日月・満ち） | メジャースケール外 |
| ⑥ | ◔系（三日月・細い） | メジャースケール上 |
| ♭7 | ◆（黒塗りひし形） | メジャースケール外 |
| ⑦ | ◇（白抜きひし形） | メジャースケール上 |

補足ルール（8/14メモより）：
- **初期段階（導入編）で使うのは ♭ が付かない ①②③④⑤⑥⑦ の7種のみ**（メジャースケール上の音）。
- ♭が付く記号（♭2, ♭3, ♭5, ♭6, ♭7）は**メジャースケール外の音**で、スケールやモードが変わったときに登場する。
- 記号は12種全て確定済み。図形の**「対になる」形状ペア**（①系スター以外は原則「塗り＝♭系／中空き＝ダイアトニック系」で対応）で視覚的にペアが分かるように設計されている。

**度数の背景色（パネル色） 🆕未確定・オープン事項**

- 記号の背後に敷く「背景色」は、しおみさん（デザイナー）に色相環をベースに割り当てを依頼中。
- 方針：まず①②③…⑦（ダイアトニック7音）に「地点の移り変わりが感覚的に伝わりやすい色」を割り当て、♭2, ♭3…（半音下がった非ダイアトニック音）には**対になるような色**を割り当てる。
  - 対比コンセプト例：**光と影／陽と陰／表と裏**
- **12種類すべての背景色セットが必要**（7種だけでなく将来のモード・転調表示にも対応するため）。
- → 🆕 Figma上の度数記号一覧（12種）を確認したが、**この時点では記号のみが並んでおりグレー背景**で、背景色そのものはまだ割り当てられていなかった。**度数の背景色は引き続き未確定**。他ページ・別ノードに背景色案がある可能性もあるため、追加共有があれば確認する。
- 設計要件：背景色データはコード内に固定せず、外出しの設定オブジェクトとして管理する（v1決定事項どおり）。

### 2.2 インターバル（距離）定義 🆕Figma正データで実装用カラーコード確定

v1では「長三度／短三度／全音／半音」の4種＋将来拡張、としていたが、**実際には0〜12半音の全13段階の色が確定済み**。これにより「将来的な拡張設計」は不要になり、初回実装から全音程に対応する。

Figma上のデザインカード（node-id `10:11`〜`10:85`、13枚）から、ニュアンス文言と**実装用の正確なカラーコード（放射状グラデーション）**を取得済み。全13枚で色名ラベルと実グラデーションの印象が一致していることを確認済み。

補足：
- 色は「何半音離れているか」という**距離そのもの**に対応する（起点や方向ではなく、絶対距離ベース）。
- 6半音（トライトーン）は12半音のちょうど中央に位置するため、他と明確に区別できる「ガンメタル」を割り当てている。
- **増5度と短6度はどちらも8半音のため同色（カッパー）** ＝ 異名同音的に距離が同じものは同色で統一するというルール。
- 🆕 カードデザインは、数字（0〜12）を背景に大きく薄く（白 or 黒 12%不透明度）重ねる意匠。背景が暗い色（0,1,2,3,6,8,10）は白文字、明るい色（4,5,7,9,11,12）は黒文字（#1a1a1a）で可読性を確保している。実装時のコントラスト設計の参考にする。
- 🆕 グラデーションはFigma上でSVG放射状グラデーション（radialGradient）として実装されている。Web実装時はCSSの`radial-gradient()`等で近似可能。

**⚠️ 参考：不一致だった旧データ（node-id 18:569〜18:649）**

同じ13枚構成のカードがもう1セット存在するが（node-id `18:xxx`）、そちらは背景色とラベルの色名が一致しない検証用/旧バージョンだったため、**採用しない**。今後Figma側でこの古いセットは削除・アーカイブしてもらうと混同を防げる。

**質感要件 🆕新規**

- 「音の移動時（インターバル色）」の表現は、**背景色（度数パネル色）とパッと見で区別できる質感**を持たせる。
  - 候補：メタリックな質感 ／ 縦方向に光が走っているような見え方（ハイライト・グラデーション）
  - → 上表の色は基本的に「メタリック」指定で統一済み。0半音（木目）と6半音（ガンメタル）のみ別質感。
- インターバルごとに、**移動した距離感が感覚的にも伝わるような工夫**があるとよい（例：半音数が大きいほど質感の強さ・グラデーション幅・光沢の動きが変わる、等）→ 実装時の調整パラメータとして持たせる。

### 2.3 フレーズ定義

- 度数の並び（例：① ③ ② ④ ③ ⑤ ④ ⑥）
- 各音間のインターバル種別（自動計算 or 手動指定）→ **2.2の0〜12半音テーブルを参照して自動判定**
- 上行／下行の情報（方向演出用）

### 2.4 エピソード／レベル設定（将来の学習者モード用）

「導入編／インターバル色編／フレーズ応用編／モード・転調編」の各段階を、表示要素のON/OFFフラグの集合としてデータ化。

例：`showIntervalColor: false`, `showLabelText: false`, `allowModeChange: false` など

🆕 補足：**導入編では①②③④⑤⑥⑦（♭なし）のみを使用**というルールが確定したため、各エピソード設定には「使用可能な度数記号セット」（♭を含むか否か）というフラグも追加する。

例：`allowedDegrees: ['①','②','③','④','⑤','⑥','⑦']`（導入編）→ 後の段階で `♭2, ♭3...` を解禁

## 3. 機能要件（コアエンジン）

| 機能 | 内容 |
|---|---|
| スケール切替 | ルート音・スケール種別を指定して構成音と色マップを再計算する |
| モードチェンジ計算 | 同じ構成音のまま中心度数を変更し、②③④…という相対並びを再計算する |
| キーチェンジ計算 | 異名同音を考慮しつつ、指定キーの地図（色マップ）に切り替える |
| フレーズ再生 | 度数配列を受け取り、音→インターバル色→次の音、の順にタイミング制御して再生する |
| インターバル自動判定 | 隣接する2音の**半音差**から、0〜12半音の色テーブル（2.2）を参照して自動判定する 🆕 |
| タイミング制御 | 「音の表示時間」「インターバル色の表示時間（0.2〜0.5秒可変）」をパラメータとして持つ |
| 中心マーク管理 | 現在の中心音（トニック＝①/☆）をパネル色とは別レイヤーで表示・更新する |
| 記号レンダリング 🆕 | 2.1の12種記号（☆▭▲△□●○◐◔◆◇等）をSVG等で描画するコンポーネントを持つ |
| 質感レンダリング 🆕 | インターバル色に対してメタリック／光沢質感を適用するレイヤーを、背景色レンダリングとは別に持つ |

## 7. 非機能要件

- 画面比率：縦長固定、iPhone全画面（9:16）を基準にレスポンシブ
- パフォーマンス：アニメーションはCSS/JSベースで滑らかに60fps程度を目標
- フォント：ヒラギノ丸ゴ系を基本とし、Web環境でのフォールバックも考慮
- 配色データ（背景色・インターバル色・記号）は外部から差し替え可能な設計にしておく 🆕（背景色は特に未確定のため要調整前提）
- 🆕 度数背景色とインターバル移動色は、**質感（メタリック／光沢の有無・種類）で明確に区別できる**ように実装する
